# Fonts (SPEC 15, prompt 9.2)

- `@fontsource/noto-sans@5.3.0` (latin 400 + 600) and `@fontsource/noto-sans-devanagari@5.3.0` (devanagari 400 + 600), self-hosted through Vite (`font-display: swap` is baked into the fontsource CSS). Pinned after `npm view` (2026-07-19 release, latest).
- **Why this dependency and not alternatives:** the spec requires self-hosted Noto Sans Devanagari; @fontsource is just pre-split Google Fonts files with no runtime JS. It replaces (a) a Google Fonts CDN link (privacy: no third-party request, works offline once precached) and (b) system fonts (iOS Safari has no Devanagari Noto guaranteed and low-end Android WebView fallbacks render Hindi with inconsistent metrics; the spec calls for a specific family with `font-display: swap`).
- **Only the weights and subsets used** are imported: `latin-400/600.css` and `devanagari-400/600.css`. No italic, no other weights, no cyrillic/greek subsets. Hindi body sits at 1.1x Latin size (`:lang(hi)`) per SPEC 15.
- **Bundle-size effect (measured):** each weight+subset woff2 is precached as a separate asset by the PWA shell, loaded only when the glyphs' unicode-range matches: latin 400 ≈ 17 KB, latin 600 ≈ 17 KB, devanagari 400 ≈ 15 KB, devanagari 600 ≈ 15 KB (about 64 KB total transferred on first paint, gzip-brotli compressed by the CDN; they are font assets, so they do NOT count against the 150 KB JS budget). Vite hashes and emits them under `assets/`; the JS bundle is unaffected except for the four small `@font-face` CSS rules inside the CSS bundle.
